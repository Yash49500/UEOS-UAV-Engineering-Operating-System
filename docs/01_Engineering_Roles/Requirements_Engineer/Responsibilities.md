# Purpose

This document defines the responsibilities, authority, ownership, and decision-making responsibilities of the Requirements Engineer throughout the engineering lifecycle.

The Requirements Engineer ensures that every engineering activity is driven by complete, measurable, verifiable, and traceable requirements.

---

# Role Overview

The Requirements Engineer transforms stakeholder needs and mission objectives into engineering requirements.

This role ensures that every subsystem, interface, software component, and hardware component is developed from approved requirements rather than assumptions.

The Requirements Engineer maintains the integrity of the System Requirements Specification (SRS) throughout the project lifecycle.

---

# Primary Responsibilities

## Stakeholder Requirement Analysis

The Requirements Engineer shall:

- Analyse stakeholder needs.
- Capture customer expectations.
- Identify operational constraints.
- Resolve conflicting stakeholder requirements.
- Document stakeholder priorities.

### Deliverables

- Stakeholder Requirement Report
- Requirement Register

---

## System Requirements Development

The Requirements Engineer shall:

- Develop functional requirements.
- Develop non-functional requirements.
- Define performance requirements.
- Define safety requirements.
- Define environmental requirements.

### Deliverables

- System Requirements Specification (SRS)

---

## Requirement Classification

Requirements shall be categorised into:

- Functional
- Performance
- Safety
- Interface
- Environmental
- Operational
- Regulatory

---

## Requirement Traceability

The Requirements Engineer shall maintain complete traceability between:

- Mission Objectives
- Stakeholder Needs
- System Requirements
- Architecture
- Implementation
- Test Cases
- Verification Results

### Deliverables

- Requirement Traceability Matrix (RTM)

---

## Requirement Allocation

Allocate approved requirements to:

- Systems Architect
- Hardware Engineer
- Embedded Systems Engineer
- AI Engineer
- Computer Vision Engineer
- Communication Engineer
- Test Engineer

### Deliverables

- Requirement Allocation Matrix

---

## Requirement Change Management

The Requirements Engineer shall:

- Review change requests.
- Assess technical impact.
- Update documentation.
- Maintain version history.
- Communicate approved changes.

### Deliverables

- Requirement Change Log

---

# Decision Authority

The Requirements Engineer has authority to:

- Approve requirement wording.
- Reject ambiguous requirements.
- Request clarification from stakeholders.
- Recommend requirement modifications.
- Maintain requirement baselines.

Final approval remains with the Chief Systems Engineer.

# Responsibility Boundaries

The Requirements Engineer is responsible for:

- Requirement quality.
- Requirement traceability.
- Requirement allocation.
- Requirement consistency.
- Requirement version control.

The Requirements Engineer is **not** responsible for subsystem implementation.

---

# Key Performance Indicators (KPIs)

Performance is measured using:

- Requirement Completeness
- Requirement Traceability
- Requirement Stability
- Verification Coverage
- Requirement Review Closure Rate
- Requirement Change Response Time

---

# Common Mistakes

Avoid:

- Writing ambiguous requirements.
- Combining multiple requirements into one.
- Using subjective terms.
- Ignoring stakeholder needs.
- Losing requirement traceability.
- Allowing uncontrolled requirement changes.

---

# Best Practices

- Write one requirement per statement.
- Make every requirement measurable.
- Assign a unique identifier.
- Maintain bidirectional traceability.
- Review requirements with stakeholders.
- Link every requirement to a verification method.
