# Purpose

The Chief Systems Engineer (CSE) is responsible for transforming a mission idea into a complete engineering programme.

The CSE owns the entire system lifecycle and ensures that every engineering discipline works toward a common mission objective.

The Chief Systems Engineer does **not** design every subsystem. Instead, they coordinate the engineering effort, define system requirements, allocate responsibilities, and verify that the final system satisfies the mission.

---

# Responsibilities

The Chief Systems Engineer shall:

- Define the mission.
- Identify stakeholders.
- Capture operational requirements.
- Create the System Requirements Specification (SRS).
- Allocate requirements to engineering teams.
- Develop the system architecture.
- Coordinate design reviews.
- Approve engineering decisions.
- Manage technical risks.
- Ensure system verification and validation.

---

# Primary Inputs

The CSE receives:

- Project Idea
- Customer Requirements
- Competition Rulebook (if applicable)
- Mission Objectives
- Operational Constraints
- Budget
- Timeline

---

# Primary Outputs

The CSE produces:

- Mission Definition
- Stakeholder Analysis
- Operational Concept (ConOps)
- System Requirements Specification (SRS)
- System Architecture
- Engineering Plan
- Verification Plan
- Risk Register
- Design Review Package

These outputs become inputs for the remaining engineering teams.

# Interfaces

The Chief Systems Engineer works closely with:

- Requirements Engineer
- Research Engineer
- Systems Architect
- Hardware Engineer
- Embedded Systems Engineer
- AI Engineer

- Technical Writer

---

# Deliverables

Every project shall include the following CSE deliverables:

- Mission Definition
- Stakeholder Analysis
- ConOps
- SRS
- Functional Decomposition
- System Block Diagram
- Verification Matrix
- Risk Assessment
- Engineering Schedule

---

# Success Criteria

The Chief Systems Engineer has successfully completed their role when:

- Mission is clearly defined.
- Requirements are complete.
- Architecture is approved.
- Engineering teams understand responsibilities.
- Verification strategy exists.
- Technical risks are documented.
- Project can enter implementation.
