# Purpose

This document defines the responsibilities, authority, ownership, and engineering boundaries of the Technical Writer within the UAV Engineering Operating System (UEOS).

The Technical Writer is responsible for ensuring that engineering knowledge is accurately documented, reviewed, version controlled, published, and maintained throughout the engineering lifecycle.

Documentation is considered an engineering deliverable and shall evolve together with the system.

---

# Role Overview

The Technical Writer manages the engineering documentation ecosystem.

The role transforms engineering outputs into structured documentation while preserving technical accuracy, traceability, consistency, and maintainability.

The Technical Writer collaborates with every engineering discipline but does not own engineering decisions.

# Decision Authority

The Technical Writer has authority to:

- Approve documentation formatting.
- Enforce documentation standards.
- Reject incomplete documentation.
- Request engineering clarification.
- Publish approved documentation.
- Manage documentation baselines.

The Technical Writer cannot:

- Modify engineering requirements.
- Approve engineering designs.
- Change implementation details.
- Make architectural decisions.
- Alter verification results.

Engineering ownership remains with the responsible engineering discipline.

# Responsibility Boundaries

The Technical Writer is responsible for:

- Documentation planning
- Documentation quality
- Documentation structure
- Documentation publishing
- Version management
- Documentation traceability
- Documentation maintenance

The Technical Writer is **not** responsible for:

- Engineering design
- Software implementation
- Hardware implementation
- Test execution
- Safety approval
- System architecture

# Common Mistakes

Avoid:

- Publishing undocumented features.
- Copying outdated information.
- Breaking traceability.
- Mixing implementation details with user instructions.
- Inconsistent terminology.
- Missing version information.
- Publishing without technical review.

---

# Best Practices

- Write for the intended audience.
- Keep documents modular.
- Reuse approved templates.
- Maintain one source of truth.
- Record assumptions.
- Use diagrams where appropriate.
- Review documentation after every engineering change.
- Archive superseded documentation rather than deleting it.
